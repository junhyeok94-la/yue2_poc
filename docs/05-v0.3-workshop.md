# v0.3 — Song Structure & Lyrics Workshop

제품 원칙: **AI assists. You compose.** 가사나 구조를 자동으로 덮어쓰지 않는다.

## 사용

`.\web-studio.ps1` 실행 후 http://127.0.0.1:7860 을 연다.
새 초안은 Section 추가로 시작한다. Intro, Verse, Pre-Chorus, Chorus, Post-Chorus,
Bridge, Breakdown, Outro, Instrumental, Custom을 지원한다.

각 카드에서 이름·마디 수·가사를 직접 작성한다. ↑/↓로 순서를 바꾸고, 삭제 직후
되돌리기로 복구한다. Guide의 마디 버튼은 사용자가 눌렀을 때만 적용된다.
가사 분석과 YuE2 가사 미리보기를 확인한 뒤 기존 음악 만들기 버튼으로 생성한다.
라이브러리에서 구조를 확인하고 가사·설정 가져오기로 편집할 수 있다.

기존 브라우저 초안과 v1 곡은 원문 모드로 불러온다. Section 편집을 누르면 변환
미리보기가 나오며 변환 적용을 눌러야 바뀐다. 알 수 없는 헤더는 Custom의 원문에 남는다.
반대로 원문 모드로 바꾸면 구조 정보가 가사 문자열에 포함되지 않는다고 확인을 받는다.

## 데이터 계약

- Song schema_version=2, title, sections, music_settings.advanced_prompt.
- Section: id, type, label, bars(null 또는 1~128 정수), lyrics(행 배열).
- 배열 순서가 유일한 순서이며 Section ID는 이동해도 유지된다.
- 최대 64개 Section, 제목 160자, 스타일 2,000자, 최종 컴파일 가사 12,000자.
- 구조화 생성은 metadata schema_version=2. 기존 평면 CLI/API 생성은 v1.
- v2 input에는 기존 title/style/lyrics/seed/steps/threads/timeout/cot 필드를 유지하고
  song, compiled_lyrics, compiler_version=1을 추가한다.
- input.lyrics와 compiled_lyrics는 같다. Song은 작업 시작 시 복사해 실패 결과에도 보존한다.
- v1/버전 없는 metadata를 그대로 읽으며 기존 파일을 마이그레이션하지 않는다.
- replay는 저장된 가사/설정을 그대로 사용한다. 재컴파일하지 않는다.
- 편집 후 새 생성은 현재 컴파일러를 사용한다.
- 새 브라우저 초안 키는 music-studio-draft-v3. 기존 키를 삭제하지 않는다.
- 검증/컴파일/분석은 domain, lyrics, metadata 모듈로 분리했다.
- cli.generate 함수 시그니처, 엔진 실행, 잠금, GPU 수집, WAV 검사는 유지했다.

## API

| 경로 | 역할 |
|---|---|
| GET /api/workshop | 타입·가이드·마디 선택지·이유 |
| POST /api/song/preview | {song} 검증, 컴파일 가사·분석·경고 반환 |
| POST /api/song/import | {lyrics}를 Section 초안으로 변환; 저장이나 생성 없음 |
| POST /api/jobs | 기존 평면 입력 또는 {song, seed, steps, threads, timeout, cot} |
| GET /api/state | 기존 상태/라이브러리 + schema_version 및 input.song |
| POST /api/replay | 기존 {id}, 저장된 입력 재사용 |

Song과 평면 title/style/lyrics를 동시에 보낼 수 없다. Song 생성 텍스트는 서버가 만든다.
Song 요청은 128KiB, 기존 평면 생성/replay는 64KiB 본문 한도다.
Host/Origin/X-Studio-Request 검증을 유지한다. 분석과 가이드는 모델 설치 없이 가능하다.
Windows에서 읽지 않은 요청 본문 때문에 403/413 대신 연결 초기화가 발생하는 경우를
재현하여, 거부 시 최대 1MiB·읽기 timeout 2초로 제한된 본문 폐기를 추가했다.

## 분석 및 엔진 한계

행 수는 공백 행을 제외하며 빈 행 수는 별도로 표시한다. 문자 수는 공백·문장부호를
포함하고 줄바꿈은 제외한다. 행 길이는 문자 수의 최소·최대·표준편차다.
분석용 사본만 NFC 정규화하여 한글 완성형 음절을 센다. 원문은 정규화하거나 교정하지 않는다.
영문·숫자·이모지의 가창 음절은 계산하지 않는다. 한글이 없는 행은 미집계로 표시한다.
반복 단어는 공백/문장부호 기반이며 형태소 분석이 아니다.

마디 수는 작곡 의도이며 실제 출력 길이를 강제하지 않는다. 행 수와 마디 수는 다르다.
타입은 [Verse], [Pre-Chorus] 등의 텍스트 힌트로 변환하며 label과 bars는 엔진에 보내지 않는다.
각 헤더의 정확한 음악적 실현은 보장하지 않는다. 실제 GPU 검증은 Verse/Chorus 조합이다.
빈 Section은 편집 상태에 보존하되 컴파일에서 제외하고 경고한다.
가사가 전혀 없는 곡은 생성하지 않는다. Instrumental 선택만으로 연주곡 생성을 보장하지 않는다.

LLM 연결·자동 가사 작성·드래그앤드롭·멜로디/코드 편집·DB는 이번 범위에서 제외했다.
LyricsAdvisor Protocol과 Suggestion 데이터 계약만 준비했다. 향후 제안 적용에는
section_id, line_index, source_revision, original 일치 확인이 필요하다.

## 테스트

기본 회귀 테스트는 추가 Python 패키지가 필요 없다.

```powershell
python -B -m unittest discover -s tests -v
node --test tests/test_editor.cjs
```

DOM 통합 테스트는 테스트 전용 jsdom 30.1.1이 필요하다. 실제 앱은 외부 패키지 없이 실행된다.
검증에 사용한 Node는 v24.19.0이다. 먼저 스튜디오 서버를 실행한 후:

```powershell
npm install --prefix outputs/ui-test --no-save jsdom@30.1.1
node --test tests/test_ui.cjs
```

다른 설치 위치는 MUSIC_STUDIO_TEST_DEPS로 지정할 수 있다.
DOM 테스트는 생성 POST를 가로채 GPU 작업을 시작하지 않는다.
