# v0.8 작업 영역 UX 정리

## 구현 전 분석과 결정

v0.7의 왼쪽 Composer에는 구조·음악 설정·가사·생성 옵션·ABC가 세로로 이어지고, 오른쪽 선택 곡 상세에는 악보와 버전 비교가 함께 있었다. app.js는 Library/선택/생성/버전 초안을 관리하고 SongEditor와 MusicGuide가 편집·AI 요청 상태를 따로 보유한다. 초안 저장 키는 music-studio-draft-v3이다.

기존 요소 ID와 이벤트를 유지한 채 HTML 소속을 변경하고, 탭 전환에서는 hidden/ARIA 상태만 변경하기로 했다. 변경 파일은 ui/index.html, ui/app.js, ui/style.css, 가이드 명칭/조언 펼침을 위한 ui/song-editor.js와 ui/music-guide.js, tests/test_ui.cjs이다. API가 이미 충분하므로 web.py 변경은 필요하지 않았다. 생성 코어/엔진/metadata/잠금/모니터링/라이브러리 로딩/replay/lineage는 수정하지 않는다.

구현 순서는 요소 재배치 → 탭 및 진행 상태 → 작업 이동 및 오류 처리 → 버전 관계 표현 → 기존/추가 테스트였다. 테스트에서는 숨겨진 필드의 검증과 포커스, 탭 전환 시 요청 입력/AI 제안 상태 보존을 특히 확인한다.

## 작업별 배치

| 작업 영역 | 내용 |
|---|---|
| WRITE | Song Structure, Section 순서/마디/가사, 원문 편집, 가사 분석·왜?·AI 검토, YuE2 가사 미리보기 |
| COMPOSE | Genre/BPM/Mood/Vocal/Instruments, 접힌 고급 Key, 자유 스타일/프리셋, 스타일 미리보기, 요청 시 펼쳐지는 음악 조언 |
| ARRANGE | 접힌 생성 설정(Planning/Seed/Steps/Timeout), 접힌 ABC 편집/파일 가져오기/헤더 검사, 선택 결과의 악보 보기·다운로드·수정 버전 |
| VERSIONS | 선택 결과 이름, 부모 관계, 들여쓰기/연결선 목록, 새 버전 만들기, 변경 비교, 기준/선택 버전 재생 |

제목, 현재 초안의 작성 상태, 초안 종류, 생성 요약과 “음악 만들기” 버튼은 공통 영역이다. 요약은 입력 유무를 보여주며 전체 입력 검증 완료를 뜻하지 않는다. VERSIONS 수는 **현재 라이브러리 선택 곡**의 가족 수라고 명시하여 독립 초안과 혼동하지 않게 했다.

오른쪽 Library의 필터/그룹/버전 수/재생/이름 변경/휴지통/복원/메타데이터 링크는 유지한다. 선택 상세는 SONG OVERVIEW로 이름을 바꾸고 버전/악보 작업 영역 바로가기를 제공한다. 하단 플레이어는 기존 단일 audio 요소와 다운로드를 유지하고 버전 종류를 표시한다.

## 상태와 작업 흐름

- 기본 영역 WRITE. 마지막 탭은 별도 키 music-studio-workspace-v8에 저장한다. 잘못된 값은 WRITE로 돌아간다.
- 탭 전환은 DOM을 재생성하지 않고 편집기 revision도 바꾸지 않는다. 작성 중 입력, 선택된 AI 제안, 악보 텍스트, 기존 초안이 유지된다.
- 키보드 좌/우·Home/End 탐색과 tab/tabpanel ARIA 관계를 제공한다.
- 음악 AI는 조언받기를 누를 때만 결과 영역이 열린다. 탭을 바꿨다고 AI를 호출하거나 내용을 자동 적용하지 않는다.
- 가사·설정 가져오기는 WRITE, Lyrics Revision 초안은 WRITE, Variation/Remix 초안은 COMPOSE, 악보 수정 버전은 ARRANGE로 이동한다.
- 라이브러리 선택 곡이 없으면 VERSIONS에서 안내를 보여준다. 선택 곡을 삭제하면 이동된 악보/버전 패널도 비운 상태로 전환한다.
- 생성 전 native validity를 명시적으로 확인하고 오류 필드가 속한 탭과 details를 연 뒤 포커스한다. 숨겨진 필드를 브라우저가 포커스하지 못하는 문제를 방지한다. 서버의 field/section_id도 보존하여 관련 작업 영역을 안내한다.
- 버전 목록은 기존 부모 관계로 중첩 목록을 만들며 순환/누락 기록에서도 무한 순회하지 않는다. 아주 깊은 관계는 들여쓰기를 제한하고 부모 이름을 함께 표시한다. 기존 코드의 버전 라벨 인덱스 오류도 수정했다.

## 호환성과 검증

API 및 모든 Python 구현 파일은 변경하지 않았다. metadata v1/v2와 생성 입력 구조, 생성/재생성/악보/버전 기록은 그대로다. 탭 상태는 서버 요청에 추가되지 않는다. 이번 UI 변경 확인을 위해 실제 GPU 생성이나 유료 AI 호출을 새로 수행하지 않았다.

2026-09-24:
- Python 기존 65개 테스트 통과.
- Node/DOM 18개 테스트 통과(기존 15개 + workspace 3개). 기존 가사 AI/음악 AI/라이브러리/버전/악보 동작과 요청 입력을 검증한다.
- 추가 확인: 한 개 작업 패널만 표시, 동일 DOM/초안 보존, 키보드 탐색, 탭 복원, hidden 필드 오류 시 탭/details/포커스 전환, AI 제안의 탭 간 유효성, 음악 조언의 명시적 호출, 악보 작업의 ARRANGE 이동, 버전 연결선 및 종류 표시.
- 실제 서버가 현재 정적 HTML/JS/CSS를 제공하는지 확인한다. 백엔드 재시작은 필요하지 않다.

## v0.8 최초 화면 검수 상태 — 당시 미완료

이번 지시서에 따라 모바일을 검수 대상에 포함했다. 720px 이하에서는 Composer/Library 한 열, 2×2 탭과 기존 고정 Player를 유지한다. 그리드 minmax(0,1fr), 긴 문자열 줄바꿈, 좁은 화면 필드 한 열, 버전 들여쓰기 제한을 적용했다.

다만 브라우저 도구가 Windows sandbox 초기화 단계의 helper_unknown_error로 종료되어 **실제 데스크톱/모바일 렌더링, 가로 overflow 측정, 고정 CTA와 플레이어의 겹침 검수는 완료하지 못했다.** DOM 테스트는 실제 픽셀 배치의 증거가 아니다. 따라서 모바일 정상 배치를 포함한 v0.8의 모든 완료 조건이 확인됐다고 간주하지 않는다.

브라우저 연결 복구 후 1440/1024/720/390/320px에서 탭 전환, 긴 제목/스타일/ABC, 버전 트리, 생성 오류 포커스, 플레이어/CTA, 페이지 가로 넘침을 확인해야 한다.


## v0.8.x UX polish — 2026-09-25

### 변경 전 확인 / 결정

기준 main은 0ba23b7이다. renderSongStatus가 편집 초안의 입력 상태와 selectedId로 계산한 family 수를 같은 song-progress 안에 넣고 있었다. 데이터 자체는 독립이지만 시각적으로 섞였다. 기존 Generate 영역은 이미 sticky였다. 320×568 실제 렌더링에서 CTA가 제목 입력을 가리고, CTA 하단 약 517px과 player 상단 약 453px이 겹치는 것을 확인했다.

따라서 다음과 같이 최소 변경했다.

- 현재 작업 / Current Draft에는 제목, Original 또는 분기 종류 + Draft, WRITE/COMPOSE/ARRANGE만 표시한다.
- 별도 Selected Song 영역에 선택 제목, 종류, family 전체 버전 수를 표시한다. 휴지통 기록은 `전체 N개 버전 · 휴지통 M개 포함`으로 명시한다. 미선택은 `선택된 곡 없음`이다. VERSIONS 탭에는 혼동 가능한 숫자를 추가하지 않았다.
- WRITE는 입력 유무를 `가사 입력됨`으로 표시한다. Section 모드의 비어 있는 배열/공백 가사는 입력됨으로 표시하지 않는다. COMPOSE 역시 설정 유무 표시이며 검증 통과 의미가 아니다. ARRANGE는 Optional / Melody Planning / Melody + Harmony / ABC Override로 구분한다.
- 생성 요약은 구조/음악/가사/계획을 담는 dl이다. 입력 미리보기임을 명시하고 기존 validation/revealControl을 유지한다.
- sticky CTA는 제거했다. 공통 하단 위치와 persistent player는 유지한다. 실제 모바일 높이에서 두 고정 영역이 편집 공간을 지나치게 차지하므로 추가 sticky는 채택하지 않았다.
- 긴 Library 제목/스타일과 family 제목을 줄바꿈한다. Song Overview에 종류와 전체 버전 수를 추가했다. 버전 중첩은 3단계까지, 이후 같은 들여쓰기에서 부모 이름으로 관계를 유지한다. 모바일 중첩 간격은 6px이다.
- 탭/Library 관리 버튼의 최소 높이는 44px. 입력/textarea/audio는 부모 폭을 넘지 않도록 한다. 이름 변경/Section 변환 대화상자는 같은 반응형 dialog 스타일을 사용한다.
- WRITE와 COMPOSE 설명에서 다음 작업/생성 버튼의 위치를 안내한다.

변경 파일: ui/index.html, ui/app.js, ui/style.css, tests/test_ui.cjs, 이 문서. 재현 가능한 격리 브라우저 검수를 위해 tests/manual_ui_fixture.py를 추가했다. 제품 backend, generation engine, API, metadata v1/v2, version.json, library storage, Gemini 동작은 변경하지 않았다. 기존 초안/탭 localStorage 키와 explicit apply/ignore 정책은 유지한다.

### 테스트 및 완료 범위

- 변경 전 Node 19개, 변경 후 Node 22개 통과. 기존 테스트를 삭제하거나 비활성화하지 않았다.
- Python 기존 65개 통과. metadata v1/v2, 엔진 입력, version lineage, 삭제/이름 변경 회귀 검증을 포함한다.
- 신규 UI 테스트: draft/selected 독립, Library 선택 및 workspace 변경 시 저장 초안 보존, 미선택, 휴지통 포함 버전 수 의미, 입력 유무와 validation 구분, 구조화된 생성 요약, 공통 CTA/player DOM 관계, 긴 텍스트, deep/orphan/cycle 버전의 유일 표시와 깊이 제한.
- **DOM 테스트는 실제 픽셀 배치를 보장하지 않는다.** 위 responsive 표는 실제 브라우저 렌더링과 측정을 근거로 한다.
- Scenario A: 브라우저에서 Section 변환/가사 작성→COMPOSE 다섯 설정→Generate→Library 선택→재생을 수행했다. 실제 Original 생성 성공, audio.paused=false 및 currentTime 증가를 확인했다.
- Scenario B/C/D: UI 분기/초안 이동/수정/요청은 기존 DOM 회귀 테스트로 검증했다. 실제 브라우저의 native confirm 단계에서 Input.dispatchMouseEvent/Input.dispatchKeyEvent 및 Emulation.setFocusEmulationEnabled timeout이 반복되어 **세 흐름의 브라우저 E2E는 미완료**다. 이를 API 검증으로 통과 처리하지 않는다.
- 나머지 실제 GPU 생성 및 부모 보존은 별도 API 검증으로 확인하며 아래 결과에 기록한다. 따라서 이번 변경의 구현·responsive 검수는 완료했으나, 요청서의 모든 브라우저 E2E 완료 조건을 충족했다고 주장하지 않는다.

## 확인창 멈춤 수정 — 2026-09-25 후속

위의 브라우저 E2E 미완료 기록은 b2010e2 당시 결과다. 원인 경로는 초안 교체 시 동기식 window.confirm 호출이었다. 해당 창을 여는 클릭/키 입력과 이후 화면 조회가 Codex in-app 브라우저 자동화에서 시간 초과됐다. 도구 내부 원인을 확정하거나 Codex 자체를 수정한 것은 아니다.

가사·설정 가져오기, 새 버전 분기, 악보 수정 버전의 초안 교체 확인을 공통 HTML dialog와 Promise 기반 처리로 교체했다. native confirm을 무시하거나 자동 승인하지 않는다. 기본 포커스는 취소이고, 취소/Esc는 편집 내용을 유지하며 원래 버튼으로 포커스를 돌린다. 적용 후에만 초안을 교체한다. 확인창 중 중복 요청을 막고, 대기 중 선택/삭제/생성 상태가 바뀌면 적용을 중단한다. API/엔진/metadata는 변경하지 않았다.

회귀 검증: Node 23개, Python 65개 통과. 기존 버전·악보 테스트의 확인/취소 절차를 새 dialog에 맞춰 유지하고, 미적용 초안 보존/Esc/포커스/중복 요청/선택 변경 후 적용 거부 테스트를 추가했다. 실제 브라우저에서 확인창 열기→Esc→다시 열기→적용→WRITE 이동을 통과했다. 다섯 viewport의 dialog/버튼 경계가 화면 안에 있고 가로 넘침은 0px이다. 320px 스크린샷으로도 확인했다.
