# v0.4 — Gemini AI Lyrics Assistant

Section 편집 카드의 **AI Lyrics Assistant**에서 가사 검토, 라임 검토, Hook 강화 또는 다음 1~2줄 제안을 누른다.
원문 / 제안 / 이유를 확인한 뒤 적용 또는 무시를 선택한다. 자동 요청·자동 적용은 없다.
검토에서 바꿀 필요가 없다고 판단하면 제안이 없을 수 있다.

## 설정

프로젝트 루트 .env (또는 서버 프로세스 환경변수):
```dotenv
GEMINI_API_KEY=발급받은키
GEMINI_MODEL=gemini-2.5-flash
```

환경변수가 .env보다 우선한다. 변경 후 서버를 재시작한다.
.env와 .env.*는 Git에서 제외하며, 빈 키를 포함한 .env.example만 공유한다.
키는 브라우저/metadata/요청 URL에 포함하지 않고 Google 요청의 x-goog-api-key 헤더에만 사용한다.
키가 없어도 기존 편집·분석·음악 생성·replay가 작동한다.

## 전송과 제한

요청 버튼을 누르면 선택한 Section의 가사·타입·이름·마디 수 및 곡 제목·스타일을 Google로 전송한다.
다른 Section, 생성 음원, 로그는 전송하지 않는다. 사용량은 Gemini 프로젝트의 요금/할당량을 따른다.
Section당 4,000자·100행, 검토 최대 3개 제안, 추가 가사 최대 2행인 제안 1개.
동시 요청 1개, HTTP timeout 60초, 출력 최대 2,048토큰, 응답 본문 256KiB.
자동 재시도는 하지 않는다. Gemini 2.5 Flash는 이 짧은 작업에서 thinkingBudget=0을 사용한다.

POST /api/advisor: {action: review, rhyme, hook 또는 suggest, section, context: {title, style}}
GET /api/advisor: configured/model/provider만 반환한다. 실제 API 연결 여부가 아닌 설정 여부다.
기존 Host/Origin/X-Studio-Request 검증을 동일하게 적용한다.

응답의 구조, 종료 상태, 원문·행 위치, 제안 개수·길이를 서버에서 검증한다.
검토는 기존 한 행 교체, 다음 줄 제안은 Section 끝에 추가한다.
제안 후 편집기 내용이 바뀌면 적용을 막는다. 한 제안을 적용한 뒤에도 남은 제안은
오래된 원문 기준이므로 다시 검토해야 한다.
제안은 메모리에만 보관하며 새로고침으로 사라진다. 적용된 가사는 기존 초안 저장과
metadata v2 생성 흐름을 따른다. 원문 모드에서는 Section으로 변환한 뒤 사용한다.

## 검증 (2026-09-24)

- Python 39개 통과 (기존 31개 + Gemini/설정/API 8개).
- JavaScript 5개 통과 (이동·삭제 2개 + DOM 3개).
- DOM: 자동 덮어쓰기 없음, 명시적 적용/무시, 요청 중 편집한 경우 늦은 응답 적용 차단,
  다음 2행 추가 확인. 모의 Gemini를 사용하므로 테스트가 과금 요청을 보내지 않는다.
- 실제 Gemini: 자체 작성한 짧은 한국어 가사로 review와 suggest를 호출해 성공.
  review의 제안 있는 응답과 빈 응답, suggest의 1개 제안을 확인했다.
- 초기 응답 개수 오류는 적용하지 않고 거절했으며 추가 제안 스키마를 maxItems=1로 강화했다.
- 400/401/403/404/429/서버 오류/timeout에서 원본 오류나 키를 사용자에게 노출하지 않는 테스트.
- 실제 브라우저 제어 도구는 기존 Windows sandbox setup 오류로 시작되지 않았다.
  따라서 데스크톱 렌더링 검수는 미완료다. 모바일 검수는 사용자 요청으로 범위에서 제외했다.

실행: .\web-studio.ps1
테스트: python -B -m unittest discover -s tests
DOM 테스트 준비/실행은 docs/05-v0.3-workshop.md 참고.

## 라임·Hook 전용 검토 보완

- **라임 검토**: 현재 Section의 다른 행과 끝소리·모음·내부 운율의 연결을 살핀다.
  의미와 자연스러운 표현을 보존하고, 연결되는 원문 구절과 소리를 이유로 설명하도록 요청한다.
- **Hook 강화**: 핵심 감정·짧고 기억하기 쉬운 구절·자연스러운 반복을 검토한다.
  Section 역할과 작가 의도를 유지하며 멜로디 품질이나 대중성을 보장하지 않는다.
- 두 요청 모두 기존 한 행을 교체하는 제안이며 최대 3개다. 다른 행은 원문 그대로인
  상태에서도 각 제안을 사용할 수 있도록 요청한다. 유용한 수정이 없으면 빈 목록을 반환한다.
- 요청별 JSON 스키마와 서버 검증에서 rhyme/hook 유형을 고정한다.
- 모든 제안 카드에 표현/음절 균형/라임/Hook 강화/아이디어 유형을 표시한다.
- 적용·무시와 원문 변경 시 적용 차단은 동일하게 유지한다.

보완 검증: Python 42개, JavaScript 7개 통과.
전용 프롬프트·스키마·잘못된 유형 거절·빈 가사·API·유형 표시·적용/무시·변경 충돌을 확인했다.
직접 작성한 한국어 Chorus로 실제 Gemini 요청: 라임 제안 2개, Hook 제안 1개 성공.
실제 데스크톱 렌더링 검수의 기존 도구 제한은 그대로이며 DOM 검증과 구분한다.
