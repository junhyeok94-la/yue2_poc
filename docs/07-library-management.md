# 라이브러리 이름 변경·삭제·복원

라이브러리에서 곡을 선택한 뒤 **이름 변경** 또는 **삭제**를 누른다.
이름 변경은 목록·검색·선택 상세·플레이어의 표시 이름에 반영된다.
생성 당시 제목과 Song/가사/설정은 그대로 유지되므로 같은 설정 재생성은 원래 입력을 사용한다.

삭제는 확인 후 휴지통 상태로 전환한다. **휴지통** 탭에서 곡을 선택하고 **복원**하면
변경했던 표시 이름까지 복구된다. 영구 삭제가 아니므로 디스크 공간은 비워지지 않는다.
기존 출력 폴더·WAV·metadata·로그를 이동하거나 제거하지 않고 library.json에 title/deleted를
원자적으로 저장한다. 경로를 유지하므로 기존 metadata의 audio_path도 유효하다.

휴지통 곡은 일반 목록에서 제외하며 웹 재생·다운로드·replay를 차단한다.
원본 metadata 열람은 가능하다. 별도 CLI에 파일 경로를 직접 전달하는 작업은 기존 동작을 유지한다.
생성 중에는 이름 변경·삭제·복원을 차단한다. 다른 탭의 변경 사항은 상태 조회로 반영한다.

API: POST /api/tracks/rename {id,title}, /api/tracks/delete {id}, /api/tracks/restore {id}.
GET /api/state의 tracks는 일반 목록, trash는 휴지통 목록이다.
이름은 줄바꿈 없이 1~160자. 기존 Origin/Host/요청 헤더·run ID 경로 검증을 유지한다.

검증: Python 46개, JavaScript 11개 통과.
임시 파일로 원본 metadata/WAV 바이트 보존, 재시작 후 이름/휴지통 보존, 복원,
생성 중 차단, 경로/Origin/이름 검증을 확인했다.
DOM에서 이름 변경·검색·플레이어 갱신, 삭제 취소, 재생 중 선택 해제, 휴지통 복원을 검증했다.
실제 사용자 곡은 테스트에서 이름을 바꾸거나 삭제하지 않았다.

## 플레이리스트에서 관리

이름 변경·삭제는 Song Overview에서 라이브러리의 각 곡 항목으로 이동했습니다. 곡을 선택하지 않고 바로 관리할 수 있으며 관리 버튼은 곡 재생 버튼과 분리되어 있습니다. 휴지통에서도 각 항목의 복원 버튼을 사용합니다. 삭제 확인, 생성 중 관리 잠금, 기존 원본/metadata 보존은 유지합니다. 선택하지 않은 곡을 관리할 때 현재 선택과 재생을 바꾸지 않는 DOM 테스트를 추가했습니다.
