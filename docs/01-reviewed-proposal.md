# Local AI Music Studio — 검토·수정 기획안

검토일: 2026-09-23. 원문은 `original-proposal.md`에 보존한다.

## 결론

자연어 → 곡 기획 → 가사 → 음악 → 라이브러리라는 최종 방향은 유지한다.
첫 목표는 Windows / RTX 3060 12GB에서 직접 작성한 Style + Lyrics로 실제 WAV를 만드는 것이다.
성공을 가정하지 않고 짧은 영어 가사, 한국어 가사, 긴 곡 순으로 실행 증거를 쌓는다.

## 원안 수정 사항

| 원안 | 수정 및 이유 |
|---|---|
| YuE2 + GGUF 지원 엔진 | audio.cpp v0.8.1 Windows CUDA 배포와 해당 엔진용 GGUF를 한 쌍으로 고정한다. 서로 다른 변환기의 GGUF 호환성을 가정하지 않는다. |
| Q4 / Q5 비교 | 선택한 배포의 Q4_0 / Q8_0을 비교 대상으로 한다. 첫 실행은 Q4_0. Q8은 Q4 성공 및 메모리 여유 확인 후 진행한다. |
| 단일 음악 모델 다운로드 | 본체, F16 VAE, 4개 sidecar(모델·생성·VAE 설정과 tokenizer)가 필요하다. |
| Python / PyTorch / CUDA / FFmpeg 필수 | Python은 CLI 관리 계층, 추론은 audio.cpp. CUDA 빌드의 필요한 런타임 DLL을 사용한다. PyTorch와 CUDA Toolkit은 사전 빌드 경로에서 필수가 아니다. FFmpeg는 MP3 변환 단계에서 도입한다. |
| 12GB에서 안정 실행 | 검증 목표다. 배포자의 RTX 5090 측정치는 RTX 3060 보증이 아니다. 곡 길이, 다른 앱의 GPU 점유, RAM과 오프로딩 영향을 측정한다. |
| 한국어 R&B를 대표 성공 기준으로 사용 | 공식 카드의 언어는 영어·중국어다. 영어로 파이프라인을 먼저 검증하고 한국어 발음·가사 일치도는 별도 청취 평가한다. |
| 멜로디·코드 제어를 미지원 미래 기능처럼 취급 | YuE2는 ABC 악보 기반 계획·조건부 생성을 제공한다. 지원 여부와 이 프로젝트가 구현할 편집 UX를 구분한다. MVP에서는 제외한다. |
| seed만으로 재현 | 입력, seed, 엔진 버전/해시, 모델 revision/해시, 실제 실행 인자까지 기록한다. 같은 설정도 장치·런타임 차이에 따른 비트 단위 동일성을 보장하지 않는다. |

## MVP 범위

- CLI 환경 진단, 입력 검증, 실행 인자 미리보기, 단일 생성 작업 실행.
- Style과 섹션 태그를 포함한 UTF-8 가사 파일 입력.
- 실행별 독립 디렉터리: WAV, 원본 입력, metadata, 엔진 로그, GPU 사용량 표본.
- 정상 종료와 읽을 수 있는 비어 있지 않은 WAV를 모두 확인해야 성공 처리.
- 실패·타임아웃·중단도 상태와 원인을 보존. 실패 결과를 성공 음원으로 표시하지 않는다.
- 동시에 한 작업만 실행해 메모리 경합을 줄인다.

UI, LLM, DB, MP3, 자동 품질평가, 악보 편집은 첫 MVP에 포함하지 않는다.
파일 기반 이력으로 시작하고 검색·수정 요구가 생기면 SQLite를 추가한다.

## 실제 환경 관측

- GPU: NVIDIA GeForce RTX 3060 / 12288 MiB, 드라이버 610.88.
- RAM: 약 31.9 GiB, 확인 시점 가용 약 10.6 GiB. 가용량은 실행마다 변한다.
- D 드라이브 여유 약 285 GiB. 작업 폴더는 비어 있었다.
- PATH의 Python launcher는 실행 실패. 별도로 확인한 Codex 번들 Python 3.12.14는 실행 가능하다.
- FFmpeg / CUDA Toolkit은 PATH에서 확인되지 않았다. 미설치라고 단정하지 않는다.

## 검증과 수용 기준

1. 영어 짧은 가사로 CUDA 생성 1회 성공, WAV 헤더/프레임/샘플레이트 검사.
2. 입력과 실행 설정, 소요 시간, 장치 전체 VRAM 표본 최고치 저장. 이는 프로세스 전용 VRAM이나 정확한 순간 최고치가 아님을 표시.
3. 사람이 파일을 재생해 보컬·반주·가사 반영·잡음·끝부분 잘림을 확인. 파일 검사를 음악 품질 통과로 간주하지 않는다.
4. 같은 설정의 반복 생성 3회와 긴 곡 테스트 후에만 ‘안정화 완료’로 표시.
5. 한국어 시험 결과는 영어와 별도로 기록. 한국어가 부적합하면 후속 모델 비교의 근거로 삼는다.

코드 테스트만 통과하면 ‘CLI 구현 완료’, 실제 CUDA WAV가 나오면 ‘첫 생성 성공’, 반복·청취 기준까지 충족하면 ‘Phase 1 안정화 완료’다.
